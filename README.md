# TG English Bot — бот для постепенного изучения английского

Каждые ~30 минут бот присылает в Telegram новое слово/фразу либо повторение
уже пройденного (по системе интервальных повторений, Leitner), с озвучкой и
опциональной картинкой по контексту. Уровень (A1→C2) растёт автоматически по
мере усвоения слов.

## Как это работает

1. **Словарь** (`data/vocabulary.json`) — список слов/фраз, размечен по
   уровням CEFR (A1, A2, B1, B2, C1, C2). Каждая запись:
   ```json
   {
     "id": "b1_procrastinate",
     "en": "procrastinate",
     "ipa": "/prəʊˈkræstɪneɪt/",
     "ru": "тянуть время, откладывать",
     "example_en": "I always procrastinate before exams.",
     "example_ru": "Я всегда тяну время перед экзаменами.",
     "level": "B1",
     "type": "word"
   }
   ```
   Можно добавлять `"type": "phrase"` для устойчивых выражений — формат тот же.

2. **Состояние** (`data/state.json`) — что уже отправлено, на каком слове
   пользователь, когда каждое слово нужно повторить снова (Leitner boxes:
   box 0 → следующее повторение через 1 запуск, box 1 → через 3, box 2 → 7,
   box 3 → 16, box 4 → 35 запусков; при запуске раз в 30 минут это примерно
   30 мин / 1.5 ч / 3.5 ч / 8 ч / 17.5 ч — можно менять в `config.py`).

3. **Логика выбора** (`src/scheduler_logic.py`) при каждом запуске:
   - если есть слово, для которого подошёл срок повторения — шлём его как
     повторение (box увеличивается, если это не первый показ);
   - иначе берём следующее новое слово текущего уровня;
   - когда слова уровня закончились — уровень поднимается на один шаг.

4. **Доставка в Telegram** (`src/telegram_client.py`):
   - `sendPhoto` с подписью (слово, транскрипция, перевод, пример) —
     если удалось найти картинку по теме слова (Unsplash API, опционально);
   - иначе `sendMessage` с тем же текстом;
   - следом `sendVoice` — произношение слова, сгенерированное через gTTS
     (Google Text-to-Speech, английское произношение), опционально.

5. **Расписание**: GitHub Actions workflow (`.github/workflows/schedule.yml`)
   с `cron: '*/30 * * * *'`, плюс `workflow_dispatch` для ручного запуска.
   После каждого запуска состояние (`data/state.json`) коммитится обратно в
   репозиторий, чтобы прогресс сохранялся между запусками (раннеры GitHub
   Actions не хранят файловую систему между запусками).

## Формат сообщения

Продуман для максимального усвоения (принципы active recall + контекст):

```
📘 Уровень B1 · Новое слово

procrastinate /prəʊˈkræstɪneɪt/
тянуть время, откладывать

📝 I always procrastinate before exams.
   Я всегда тяну время перед экзаменами.
```

Для повторений добавляется пометка `🔁 Повторение №N`, чтобы было видно,
что это уже знакомое слово, а не новое.

## Установка

1. Создайте бота через [@BotFather](https://t.me/BotFather), получите
   `BOT_TOKEN`.
2. Узнайте свой `CHAT_ID` (напишите боту, затем откройте
   `https://api.telegram.org/bot<TOKEN>/getUpdates` и найдите `chat.id`,
   либо используйте @userinfobot).
3. (Опционально) зарегистрируйтесь на [unsplash.com/developers](https://unsplash.com/developers)
   и получите `UNSPLASH_ACCESS_KEY` — для картинок по контексту слова.
   Без ключа бот просто не будет прикреплять картинку.
4. Создайте репозиторий на GitHub, залейте туда содержимое этой папки.
5. В Settings → Secrets and variables → Actions добавьте секреты:
   - `BOT_TOKEN`
   - `CHAT_ID`
   - `UNSPLASH_ACCESS_KEY` (опционально)
6. Workflow запустится сам по расписанию, либо запустите вручную во вкладке
   Actions → "Send English lesson" → Run workflow.

## Локальный запуск (для отладки)

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # впишите BOT_TOKEN и CHAT_ID
python -m src.main
```

## Важные ограничения, о которых стоит знать

- **Точность cron в GitHub Actions не гарантирована.** GitHub сам пишет, что
  запуски по расписанию могут задерживаться на несколько минут в периоды
  нагрузки, а при высокой загрузке платформы — пропускаться. Для строгих
  "ровно каждые 30 минут" это не подходит; для обучающего бота — вполне
  приемлемо.
- **GitHub автоматически отключает scheduled workflows после 60 дней без
  активности** в репозитории (без единого коммита/запуска). Разово зайдите
  и нажмите "Enable workflow", либо настройте что-то, что коммитит в репо
  регулярно (наш скрипт как раз коммитит `state.json` — это само по себе
  считается активностью и должно предотвращать отключение).
- Если нужна гарантированная точность интервала — надёжнее перенести запуск
  на VPS/сервер с обычным `cron` или systemd timer (код бота от этого не
  зависит, workflow — просто один из способов запуска `python -m src.main`).
- gTTS обращается к публичному сервису Google для синтеза речи — сети,
  где он заблокирован, могут потребовать другой TTS-провайдер.

## Структура проекта

```
tg-english-bot/
├── .github/workflows/schedule.yml   # расписание запуска (каждые 30 мин)
├── data/
│   ├── vocabulary.json              # база слов/фраз по уровням
│   └── state.json                   # прогресс (коммитится ботом автоматически)
├── src/
│   ├── config.py                    # настройки и переменные окружения
│   ├── vocabulary.py                # загрузка словаря
│   ├── state_manager.py             # чтение/запись state.json
│   ├── scheduler_logic.py           # выбор следующего слова (Leitner)
│   ├── image_provider.py            # картинка по контексту (Unsplash)
│   ├── tts_provider.py              # озвучка произношения (gTTS)
│   ├── telegram_client.py           # отправка в Telegram
│   └── main.py                      # точка входа
├── requirements.txt
└── .env.example
```

## Расширение словаря

Просто добавляйте объекты в `data/vocabulary.json` — состояние подхватит
новые слова автоматически при следующем запуске, ничего пересчитывать не
нужно. Уровни, которые бот проходит по порядку, задаются в `src/config.py`
(`LEVEL_ORDER`).
